contextcontexto

The dashboard had 16 views. The assistant lets people ask in plain language where a number lives, or prepare an action, instead of hunting through screens.El dashboard tenía 16 vistas. El asistente permite preguntar en lenguaje natural dónde está un número, o preparar una acción, en vez de buscar entre pantallas.

problemproblema

A model that only talks cannot read live data, and a model that can act can do damage. It also had to survive a free-tier quota, a provider that sometimes writes a tool call as plain text, and users who expect the first words fast.Un modelo que solo conversa no puede leer datos en vivo, y uno que puede actuar puede hacer daño. Además debía sobrevivir a una cuota gratuita, a un proveedor que a veces escribe la llamada a herramienta como texto y a usuarios que esperan las primeras palabras rápido.

what I built, and whyqué construí y por qué
  • Provider-agnostic. It speaks the OpenAI-compatible protocol, so the model is swapped by environment variables. Why: no lock-in, and a second model can sit behind the first as fallback.Agnóstico de proveedor. Habla el protocolo compatible con OpenAI, así que el modelo se cambia con variables de entorno. Por qué: sin dependencia, y un segundo modelo puede respaldar al primero.
  • A capped tool loop. Up to 6 turns over about 21 tools: sales, targets, team activity, a how-to guide of the system, and preparing a form from dictation. Why: a cap bounds cost and stops runaway loops. trade-off a rare long question is cut off and has to answer with what it has.Un bucle de herramientas acotado. Hasta 6 turnos sobre unas 21 herramientas: ventas, metas, actividad del equipo, una guía de uso del sistema y preparar un formulario desde un dictado. Por qué: el tope acota el costo y evita bucles sin fin. trade-off una pregunta larga y rara se corta y debe responder con lo que tiene.
  • NDJSON streaming with typed events. Status, text and action buttons arrive as separate events. Why: the interface can show that it is looking up data at once, and buttons are structured data, not parsed from prose.Streaming NDJSON con eventos tipados. Estado, texto y botones de acción llegan como eventos separados. Por qué: la interfaz muestra de inmediato que está consultando y los botones son datos estructurados, no texto que se interpreta.
  • It never writes without a Confirm button. The agent only prepares the action; the person presses confirm. Why: the model is probabilistic and a write cannot be undone.Nunca escribe sin un botón Confirmar. El agente solo prepara la acción; la persona pulsa confirmar. Por qué: el modelo es probabilístico y una escritura no se deshace.
  • Memory, cache and a usage counter. Per-user persistent memory, a response cache, and a daily counter that watches the free quota. trade-off a cache trades freshness for speed and quota.Memoria, caché y contador de uso. Memoria persistente por usuario, caché de respuestas y un contador diario que vigila la cuota gratuita. trade-off una caché cambia frescura por velocidad y cuota.
  • A rescue parser. When the model emits the tool call as text instead of the structured field, the parser detects it and runs it. Why: it is a known failure of some models, and recovering it is cheaper than retrying the request.Un parser de rescate. Cuando el modelo emite la llamada como texto en vez de usar el campo estructurado, el parser la detecta y la ejecuta. Por qué: es una falla conocida de algunos modelos y recuperarla sale más barato que repetir la solicitud.

contextcontexto

The same discipline applies to a model's answer and to a query that replaces a report: define the yardstick first, then measure.La misma disciplina sirve para la respuesta de un modelo y para una consulta que reemplaza un reporte: definir primero la vara y luego medir.

problemproblema

Prompt edits and query rewrites change results silently. Without a fixed yardstick, "it seems better" is the only evidence.Cambiar un prompt o reescribir una consulta altera resultados sin avisar. Sin una vara fija, "parece mejor" es la única evidencia.

what I built, and whyqué construí y por qué
  • A golden-set evaluator. It replays real questions from the chat log against the chat endpoint and scores each answer with heuristics: answers first, does not leak tool names, does not narrate its steps, uses chat formatting. Why heuristics: cheap, deterministic, a few seconds per prompt change. trade-off they check form, not truth. Truth is checked by the next items.Un evaluador con conjunto de referencia. Repite preguntas reales del log contra el endpoint del chat y puntúa cada respuesta con heurísticas: responde primero, no filtra nombres de herramientas, no narra pasos, usa formato de chat. Por qué heurísticas: baratas, deterministas, unos segundos por cambio de prompt. trade-off revisan la forma, no la verdad. La verdad la revisan los puntos siguientes.
  • A prompt written from a spec. The system prompt comes from a reasoning-quality spec, so each rule in the prompt maps to something the evaluator can score.Un prompt escrito desde una especificación. El prompt de sistema sale de una especificación de calidad de razonamiento, de modo que cada regla se corresponde con algo que el evaluador puede puntuar.
  • Parity as a hard rule. A SQL query that replaces a measure of a BI model is not connected until it matches the model digit by digit. The model spec (148 measures, 43 live views) is regenerated from the BI project files, never edited by hand, so a diff shows exactly what changed.Paridad como regla dura. Una consulta SQL que reemplaza una medida de un modelo BI no se conecta hasta coincidir dígito por dígito con el modelo. La especificación (148 medidas, 43 vistas vivas) se regenera desde los archivos del proyecto BI y nunca se edita a mano, así un diff muestra qué cambió.
  • Control numbers. Every breakdown must add up to the period total and state its coverage. Assertions use closed months only, because the current month is corrected backwards.Números de control. Todo desglose debe sumar el total del periodo y declarar su cobertura. Las aserciones usan solo meses cerrados, porque el mes en curso se corrige hacia atrás.
  • Reproducibility. Numbered scripts and frozen snapshots. Running with the snapshot flag regenerates the pages byte for byte, and a control script prints the numbers to compare. A status-audit script applies each rule to the same rows in about 10 seconds.Reproducibilidad. Scripts numerados y snapshots congelados. Ejecutar con la opción de snapshot regenera las páginas byte por byte, y un script de control imprime los números para comparar. Un script de auditoría de estados aplica cada regla a las mismas filas en unos 10 segundos.

what I learnedqué aprendí

Missing inputs must fail loudly. A monthly target that silently falls back to an earlier month makes a wrong answer look right, and a check like value >= 0 still passes. Every check now first asserts that the input row exists.Los datos faltantes deben fallar con ruido. Una meta mensual que cae en silencio a un mes anterior hace que una respuesta incorrecta parezca correcta, y una validación como valor >= 0 igual pasa. Ahora cada chequeo primero verifica que exista la fila de entrada.

contextcontexto

Three tools that lived apart became one product for field teams and supervisors, with live data.Tres herramientas que vivían separadas pasaron a ser un solo producto para equipos de campo y supervisión, con datos en vivo.

problemproblema

The logic and business rules lived inside one HTML prototype. It had to become a real multi-user product without changing a single result, and with each person seeing only their own zone.La lógica y las reglas vivían dentro de un prototipo en un solo HTML. Debía volverse un producto multiusuario real sin cambiar un solo resultado y con cada persona viendo solo su zona.

what I built, and whyqué construí y por qué
  • A written spec with a checklist. 16 views (9 for field users, 7 for supervisors and admins), so the migration could be verified view by view and a coding agent could work from it.Una especificación escrita con checklist. 16 vistas (9 de campo, 7 de supervisión y administración), de modo que la migración se verificó vista por vista y un agente de código podía trabajar desde ella.
  • Next.js 16 with a pluggable store. App Router, TypeScript and Tailwind. A factory picks the remote database when credentials exist and a local JSON file when they do not. Why: development and tests never touch production data.Next.js 16 con un almacén intercambiable. App Router, TypeScript y Tailwind. Una fábrica elige la base remota si hay credenciales y un JSON local si no. Por qué: desarrollo y pruebas nunca tocan datos de producción.
  • Roles and zone isolation on the server. Login goes through the company's central auth API (JWT). Each role sees only its zone, enforced in the data layer, not just hidden in the interface.Roles y aislamiento por zona en el servidor. El login pasa por la API central de autenticación de la empresa (JWT). Cada rol ve solo su zona, aplicado en la capa de datos y no solo oculto en la interfaz.
  • Parity tests, old against new. The same inputs go through the prototype's logic and through the new code, and the results must match.Pruebas de paridad, antiguo contra nuevo. Las mismas entradas pasan por la lógica del prototipo y por el código nuevo, y los resultados deben coincidir.
  • Latency and cache. Monthly snapshots precomputed in object storage (about 20 s to rebuild a month; closed periods are never re-fetched) plus per-user caches. trade-off a closed period can only change through a deliberate rebuild.Latencia y caché. Snapshots mensuales precalculados en almacenamiento de objetos (unos 20 s para reconstruir un mes; los periodos cerrados no se vuelven a pedir) más cachés por usuario. trade-off un periodo cerrado solo cambia con una reconstrucción deliberada.
  • Production traps, named. A shared database had a low connection ceiling that idle connections from the app and a desktop BI tool exhausted, and DATETIME values shifted five hours because the driver converted time zones, so they are now read as text.Trampas de producción, con nombre. Una base compartida tenía un tope bajo de conexiones que agotaban las conexiones ociosas de la app y de una herramienta BI de escritorio, y los DATETIME se desfasaban cinco horas porque el driver convertía zonas horarias, así que ahora se leen como texto.

contextcontexto

A full-stack tool that shows where every order stands and raises alerts when something needs a person.Una herramienta full-stack que muestra en qué estado está cada pedido y levanta alertas cuando algo necesita a una persona.

problemproblema

Status lived in three places that disagree: an internal no-code database and two courier platforms, one with a REST API and one that allows a single web session at a time. Someone had to look each order up by hand.El estado vivía en tres lugares que no coinciden: una base interna no-code y dos plataformas de courier, una con API REST y otra que permite una sola sesión web a la vez. Alguien debía buscar cada pedido a mano.

what I built, and whyqué construí y por qué
  • A cron, not live calls. A Node/Express server and a React/Vite front end. Every 10 minutes (Vercel or Railway cron, state in Redis) it pulls and merges the sources into one view. Why: the single-session platform makes on-demand calls fragile. trade-off data can be up to 10 minutes old.Un cron, no llamadas en vivo. Un servidor Node/Express y un front React/Vite. Cada 10 minutos (cron en Vercel o Railway, estado en Redis) lee y une las fuentes en una sola vista. Por qué: la plataforma de sesión única vuelve frágiles las llamadas bajo demanda. trade-off los datos pueden tener hasta 10 minutos.
  • A rules engine with explicit definitions. Delivered means a final successful courier event; partial, damaged or lost do not count, and on reshipments the highest suffix wins. Delayed counts business days, excluding holidays, over the SLA for the region type. Partial means a declared item is missing, compared by name. Also: incident, no evidence (delivery without photo) and duplicate item.Un motor de reglas con definiciones explícitas. Entregado es un evento final exitoso del courier; parcial, siniestrado o perdido no cuentan, y en reenvíos gana el sufijo mayor. Demorado cuenta días hábiles, sin feriados, sobre el SLA según el tipo de región. A medias es que falta un ítem declarado, comparado por nombre. Además: incidencia, sin evidencia (entrega sin foto) y equipo duplicado.
  • Validation and a reason taxonomy. Phone and ID document formats are checked, and each incident gets a reason from a fixed list. An LLM call checks ID document images.Validación y taxonomía de motivos. Se validan los formatos de teléfono y documento, y cada incidencia recibe un motivo de una lista fija. Una llamada a un LLM revisa imágenes de documentos de identidad.
  • Alerts and views. KPI dashboard, shipment timelines with photos, an incident list, a GPS map, monthly analysis, Excel export, and alerts in the app, on the desktop and by email.Alertas y vistas. Dashboard de KPI, líneas de tiempo de envíos con fotos, lista de incidencias, mapa GPS, análisis mensual, exportación a Excel y alertas en la app, en escritorio y por correo.
  • Read-only on every source. By design: a monitor must not be able to change what it watches.Solo lectura sobre cada fuente. Por diseño: un monitor no debe poder cambiar lo que vigila.

what I learnedqué aprendí

Writing the definitions down was the real work. Two systems can disagree on one metric only because of the denominator, median against mean, or the month they anchor to. When I reproduced an existing KPI package I documented a compatible mode instead of arguing which one was right.Escribir las definiciones fue el trabajo real. Dos sistemas pueden discrepar en una métrica solo por el denominador, mediana contra promedio o el mes en que anclan. Al reproducir un paquete de KPI existente documenté un modo compatible en vez de discutir cuál era el correcto.

contextcontexto

Everything above was built with Claude Code. My part was deciding what to build, checking every figure against the real data, and catching what the model alone does not see.Todo lo anterior se construyó con Claude Code. Mi parte fue decidir qué construir, contrastar cada cifra contra los datos reales y detectar lo que el modelo solo no ve.

problemproblema

Large repetitive tasks, like extracting structured fields from a big set of documents, are too slow by hand. But agent output cannot be trusted unchecked, and context is lost between sessions.Las tareas grandes y repetitivas, como extraer campos estructurados de un conjunto grande de documentos, son demasiado lentas a mano. Pero la salida de un agente no se puede dar por buena sin revisar, y el contexto se pierde entre sesiones.

what I built, and whyqué construí y por qué
  • Six subagents in parallel. Each takes a slice of the set and returns structured fields with a confidence. Low-confidence items go to a human review queue instead of being accepted. Why: speed from the parallelism, trust from the queue. trade-off the queue is real work for a person.Seis subagentes en paralelo. Cada uno toma un tramo del conjunto y devuelve campos estructurados con una confianza. Lo de baja confianza va a una cola de revisión humana en vez de aceptarse. Por qué: velocidad por el paralelismo, confianza por la cola. trade-off la cola es trabajo real para una persona.
  • Files linked by content. Documents are matched by hash and size, because an archive export is not a faithful copy: it renames files and drops duplicates.Archivos enlazados por contenido. Los documentos se vinculan por hash y tamaño, porque la exportación de un archivo comprimido no es copia fiel: cambia nombres y elimina duplicados.
  • Project memory. An index of 60+ verified findings, incidents and decisions, so the next session starts from checked facts and not from guesses.Memoria del proyecto. Un índice de más de 60 hallazgos, incidentes y decisiones verificados, para que la sesión siguiente parta de hechos comprobados y no de suposiciones.
  • Project skills. Reusable instructions for procedures I repeat, so each run follows the same steps.Skills del proyecto. Instrucciones reutilizables para los procedimientos que repito, de modo que cada ejecución siga los mismos pasos.
  • Visual QA. A headless-Chrome driver logs in, skips the tour, waits for the data and takes readable crops, so interface changes are checked on screen and not assumed.QA visual. Un driver de Chrome sin pantalla inicia sesión, salta el tour, espera los datos y toma recortes legibles, así los cambios de interfaz se revisan en pantalla y no se suponen.
  • Cross-check before any number. Every breakdown sums to its total, and the coverage of a join is stated.Contrastar antes de dar un número. Todo desglose suma su total y se declara la cobertura de un cruce.
